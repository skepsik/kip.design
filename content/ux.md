# Хранилище секретов — пользовательский опыт

Документ-спутник к сводному дизайну и implementation. Фиксирует, как система
**выглядит и ощущается** для пользователя. Ключи и слот — design v3 §5.2а; адаптеры —
implementation.

---

## 1. Ментальная модель

### 1.1. Два слоя

| Слой | Где | Кто задаёт структуру |
|------|-----|----------------------|
| **Дерево файлов** | RAM (tmpfs), пока развёрнуто | **Пользователь** — любые имена и вложенность |
| **Хранилище в git** | корень репозитория | **Система** — непрозрачные случайные имена; пользователь их не видит |

Источник правды — зашифрованные объекты в git. Именованное дерево **нигде не
персистится**: не в git, не на диске. Его всегда можно **воспроизвести** из объектов и
графа (`unfold`).

### 1.2. Развёрнутое состояние

Пока хранилище **развёрнуто** (`unfold` был и RAM ещё не свернули), одновременно живут:

- **RAM-дерево** — файлы и папки для работы;
- **таблица в памяти** — граф узлов (родитель, имя, ссылки, хэши).

Таблица **не персистится на диск**: свёрнутое состояние — только репозиторий
(implementation §1.1). Полные пути в таблице **не хранятся** — вычисляются из графа.

Правки в RAM **сами** таблицу не обновляют. Связка «файл ↔ узел» — на **`pack`** или
**`fold`**. До `pack` изменения только в RAM; после reboot без `pack` — потеряны.

Понятие **«сессия»** в CLI и документации **не используется**.

### 1.3. Команды в жизни пользователя

```
unfold   →  RAM-дерево + таблица в памяти
работа   →  обычные операции в RAM-дереве
pack     →  сохранить в git (упаковка + автокоммиты), RAM остаётся
fold     →  pack + свернуть RAM
git push →  иногда на remote (remote — обычный git)
```

**`unfold` / `fold`** — «показать / спрятать проекцию». **`pack`** — «записать в
хранилище, продолжаю работать».

**Одна фраза для README:** секреты как папка в RAM; в git — только шифр. Развернул —
работаешь; `pack` / `fold` фиксируют; `git push` — когда нужен другой компьютер.

## 2. Структура репозитория

Корень `secrets-vault/` **и есть** хранилище. Шифроблобы лежат **прямо в корне** — без
`objects/` и без префиксов вроде `ab/`.

```
secrets-vault/
  .git/
  .gitignore              # как минимум: .vault/
  vault-id                # открытый id репозитория (соль имён слота; design §5.2а)
  a7f3c9e2…               # шифроблоб (мета/тело/слот снаружи неотличимы)
  d4b81a0f…
  …
  .vault/                 # служебное, **не в git**, своё на каждом устройстве
      sync-marker         # метка последней применённой ревизии
      active-root         # путь к RAM-дереву, пока развёрнуто
      warnings.log
      config              # опционально: пути, не passphrase
```

В git — **блобы в корне** (включая `vault-id` и слот). Служебное — в `.vault/`.

RAM-дерево — **вне** репозитория (tmpfs), например `/run/vault/<id>/`. Путь в
`.vault/active-root`.

Пользователь не редактирует шифроблобы, `vault-id` и `.vault/` вручную.

---

## 3. Имена и идентичность

### 3.1. Дерево (пользователь)

Полная свобода имён и вложенности. Vault не навязывает схему каталогов.

### 3.2. Объекты в git (система)

У каждого узла стабильная **случайная** идентичность (`kNNN` — не инкремент). Счётчики
не используются.

- **мета** — файл в корне repo с именем = id узла;
- **тело** — отдельный файл со случайным именем, ссылка в мете;
- **слот** — blob с обёрнутым vault key; имя выводится из фразы и `vault-id` (не
  выбирается пользователем).

## 4. Команды CLI (MVP)

| Команда | Назначение |
|---------|------------|
| `kip init <путь>` | Git-репо, `vault-id`, слот, `.vault/`, `.gitignore` |
| `kip unfold <путь>` | Pull (если есть remote) → дельта → unlock → RAM + таблица |
| `kip pack` | Скан RAM → упаковка → **автокоммиты**; RAM **остаётся** |
| `kip fold` | **`pack`** + снять RAM-дерево |
| `kip sync` | Pull → обновить объекты и RAM → `pack`; опц. `--push` |
| `kip passwd` | Смена фразы; purge старого слота из истории |
| `kip purge <путь>` | Вычистить историю тел узла (нератируемый секрет; design §5.2а) |
| `kip fsck <путь>` | Сверка таблицы, объектов, слота, инвариантов графа |
| `kip history <путь>` | Ревизии тела секрета |
| `kip restore <путь>@<rev>` | Подмена файла в RAM из истории; фиксация — `pack`/`fold` |

**Remote** опционален: `git remote add/remove` вручную. Push — `git push` или
`kip sync --push`. Pull — только в `unfold` и `sync`.

**За рамками MVP:** `rotate-vk` и синхронизация эпох между устройствами
(implementation §2.6); FUSE; TUI конфликтов; chaff по умолчанию.

Правки секретов — **только** обычные операции в RAM (`vim`, `mv`, `mkdir`, `rm`).

## 5. `pack` и `fold`

### 5.1. Упаковка и коммиты — неделимо

**`pack`** (и фаза сохранения в **`fold`**) всегда:

1. скан RAM-дерева и сверка с таблицей;
2. шифрование и запись изменённых блобов;
3. **автоматическая серия git-коммитов** (один объект — один коммит; порядок: тело →
   мета, родитель → дети — design v3 §5.4).

Отдельно «только упаковать» или «только закоммитить» недоступно.

### 5.2. `fold` ≠ удаление секретов

| Действие | Что происходит |
|----------|----------------|
| **`kip fold`** | `pack` + убрать RAM; **секреты в git не трогаются** |
| **`rm` в RAM + `pack`/`fold`** | Узел удалён из актуального состояния; **история тел сохраняется** — восстановимо через `history`/`restore` |
| **`kip purge <путь>`** | Необратимо вычищает историю тел узла (явная команда, не флаг к `rm`) |

`fold` — «сохранил и спрятал вид», не «стёр vault».

### 5.3. Remote и push

Vault работает **без remote** (`git bundle` для второй копии — implementation §2.1).
Когда remote есть: pull — в `unfold`/`sync`; push — `git push` или `sync --push`.

## 6. Фраза и ключи

### 6.1. Passphrase

Источники (по приоритету для автоматизации):

1. **Файл** — `KIP_VAULT_PASSPHRASE_FILE`; права `0600`.
2. **Переменная** `KIP_VAULT_PASSPHRASE` — осторожно (видно в `ps`).
3. **Интерактивный ввод**.
4. **gpg-agent** — фраза и vault key (VK) на TTL агента; не OS-keychain.

Файл с фразой **не** в репозитории vault.

Отказы чтения фразы (`PassphraseError` в `vault-cli`): пустая фраза; env не UTF-8;
ошибка чтения файла / интерактивного ввода / прочий I/O. Stringly `Message` нет.

**Vault-id** — открытый id в git; нужен вместе с фразой, чтобы вычислить имя слота.
Потеря `vault-id` при живой фразе = потеря координат входа; чинится из любой полной
копии repo (git-история, clone, bundle).

### 6.2. Принцип слепка

Клон repo — **слепок момента времени**. Всё, что было в vault на этот момент,
принадлежит владельцу слепка **навсегда**: фраза эпохи слепка вскрывает его в любой
момент.

`passwd` и ротация VK управляют только **будущим** доступом. Утёкший слепок не
отзывается; критичные секреты внутри — заменить у эмитентов.

### 6.3. Смена фразы (`passwd`)

Смена фразы без purge старого слота из git-истории почти ничего не защищает: история
отдаст старый слот. Поэтому `passwd` **переписывает историю** слота (purge) и требует
`git push --force` при наличии remote. Другие устройства — переклон / reset по
инструкции инструмента.

История **тел и мет** — фича (версионирование); переписывается только история **слота**.

### 6.4. Ротация vault key (`rotate-vk`, аварийно)

**После MVP** (команда и синхронизация эпох — implementation §2.6; заголовок с
`vk_epoch` закладывается с первого дня, §2.2).

Против утечки пары **«слепок + фраза его эпохи»** или компрометации VK. Полное
перешифрование + отсечение истории. В обычной жизни не нужна; слабее — `passwd`
(только пока слепок не утёк).

После ротации: перечеканен слот под новый VK; force-push и переклон устройств, как
после `passwd`.

## 7. Типичные сценарии

### 7.1. Первая настройка

```bash
kip init ~/secrets-vault
cd ~/secrets-vault && git remote add origin …   # опционально
kip unfold ~/secrets-vault
cd /run/vault/…
```

### 7.2. Одна машина

```bash
kip unfold ~/secrets-vault
cd /run/vault/…
# правки в RAM
kip pack
git push                          # редко
kip fold
```

### 7.3. Второе устройство

```bash
git clone … ~/secrets-vault
kip unfold ~/secrets-vault
```

### 7.4. История и откат

```bash
kip history keys/api.key
kip restore keys/api.key@abc1234
kip pack
```

`rm` + `pack` удаляет узел из **актуального** состояния, но история тел **остаётся**.
`kip purge keys/old.key` — когда историю надо уничтожить навсегда.

### 7.5. Компрометация

«Утекла фраза, слепок ещё нет» → `kip passwd` (purge + force-push).

«Утекла пара слепок + фраза» → `kip rotate-vk`, затем §6.4; секреты — заменить у
эмитентов.

### 7.6. Конфликты

При `sync` / pull в `unfold` — design §4. Две версии рядом (`file`,
`file.conflict-<суффикс>`); выбор вручную, затем `pack`.

## 8. Безопасность (UX)

| Аспект | Поведение |
|--------|-----------|
| RAM-дерево | tmpfs; после `fold` или reboot — нет, пока снова не `unfold` |
| Таблица | Только в RAM; на диске не остаётся |
| VK / агент | VK в gpg-agent с TTL; после `fold` — сброс |
| Своп | Предупреждение при `unfold` |
| Модель угроз | Наблюдатель git/remote; локальная машина доверенная |
| Фраза | Вне scope vault: забыта при погашенных сессиях = тотальная потеря |

---

## 9. Что пользователь не делает

- Не именует и не трогает шифроблобы и `vault-id`.
- Не коммитит секреты через `git` вручную.
- Не хранит открытое дерево в repo.
- Не использует термин «сессия».
- Не путает `rm` (обратимо историей) и `purge` (необратимо).

## 10. MVP

`init`, `unfold`, `pack`, `fold`, `sync`, `passwd`, `fsck`, `history`, `restore`;
блобы в корне (заголовок упаковщика + ciphertext, `vk_epoch=1` — implementation §2.2);
`vault-id`; `.vault/`; RAM-материализация; passphrase из файла.

**За рамками MVP:** `rotate-vk`; синхронизация эпох (§2.6); FUSE; TUI конфликтов;
chaff по умолчанию.

---

## Приложение. Сводка

- Дерево **только в RAM**; таблица **только в RAM**; свёрнуто = **только repo**.
- **`pack`** = упаковка + автокоммиты; **`fold`** = `pack` + свернуть RAM.
- Remote опционален; push — `git push`; pull — в `unfold` / `sync`.
- **Одна фраза**, один слот; объекты шифруются **VK**.
- **`vault-id`** — открытый якорь; с фразой даёт имя слота.
- **`rm` обратим** историей; **`purge`** — явная необратимая зачистка тел.
- **`passwd --purge`** — переписывает историю слота; **`rotate-vk`** (после MVP) —
  аварийно всего хранилища; заголовок блоба с `vk_epoch` — с первого дня.
